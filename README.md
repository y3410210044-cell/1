# 猪・鹿 自動捕獲システム（群れ一括捕獲版）

イノシシ・シカをカメラで認識し、SwitchBot 等の作動装置で罠を発報する自動捕獲システム。

これは初版（検知したら即発報）を、**捕獲効率**の観点から全面的に再設計したものです。

---

## なぜ作り直したか — 「検知したら即発報」が効率を下げる3つの理由

罠猟の現場知見に照らすと、単純な「1頭でも写ったら罠を作動」は、実は捕獲効率を大きく損ないます。

### 1. 群れを取り逃す＝残りが「スレ個体」になる
イノシシもシカも群れで行動します。囲い罠に群れの一部（特に幼獣）だけが入った瞬間にゲートを落とすと、
外にいた成獣・警戒心の強い個体は捕れず、しかも**「あの場所は危険だ」と学習**します。
一度スレると同じ罠には二度と近づかず、その群れはほぼ捕獲不能になります。
→ **効率の本質は「1頭ずつ」ではなく「群れごと一括」で獲ること。**

### 2. 餌付け（学習）期間を無視すると罠に入らない
警戒心の強い獣は、いきなり罠の中の餌を食べません。数日〜数週間かけてゲートを固定・開放したまま
餌に慣れさせ、「ここは安全」と学習させて初めて群れ全体が奥まで入るようになります。
→ **システムには「発報しない観察・餌付けモード」が必須。**

### 3. 錯誤捕獲は「効率」でなく「違法・危険」
人（特に子供）、クマ、イヌ、そして**カモシカ（特別天然記念物、捕獲は違法）**が写っている間に
ゲートを落とすのは、効率以前に事故・法令違反です。
→ **非対象が1体でもいれば絶対に発報しない安全ロジックが最優先。**

## 再設計の核 — 「頭数を数えて、最適な瞬間にだけ落とす」

本システムは検知器の上に **群れ計数** と **捕獲判断ステートマシン** を載せています。

```
                     ┌─────────────── 錯誤捕獲チェック（最優先・常時） ───────────────┐
                     │ 人 / クマ / イヌ / カモシカ が1体でも → 即 ABORT（発報禁止＋通報）│
                     └──────────────────────────────────────────────────────────────┘

  カメラ ─(動体検知でwake)→ 検知(YOLO) ─→ 追跡＆計数(罠ROI内の頭数) ─→ 捕獲判断FSM ─→ 作動装置
   省電力                    種別分類                  群れサイズを推定           最適タイミング   SwitchBot(BLE主/クラウド副)
```

### 捕獲判断ステートマシン

| 状態 | 説明 | ゲート |
|---|---|---|
| `OBSERVING` | 餌付け・学習期。**発報しない**。来訪した群れの頭数・時間帯を記録し、その群れの「期待頭数」を学習する。 | 常時開放 |
| `ARMED` | 発報許可。罠ROI内の頭数を毎フレーム計数。 | 待機 |
| `HOLDING` | 非対象（人・クマ等）が視野内。 | **強制ロック** |
| `CAPTURED` | 発報済み。多チャンネル通報し、手動リセットまで再発報しない。 | 落下済 |

### いつ落とすか（最適発報タイミング）
`ARMED` 中、次を**すべて**満たした瞬間だけ発報します。

1. **頭数が目標に達した** — ROI内の対象頭数 ≥ `capture.target_count`
   （目標は観察期に学習した「その群れの期待頭数」。未学習なら設定値）。
2. **これ以上増えない** — 直近 `stability_seconds` 秒、頭数が増加していない（＝群れが出そろった）。
3. **ゲート際に個体がいない** — ゲート付近ゾーンに獣がいない（落下で挟まない・驚かせない）。

加えて **離脱エッジ検知**：頭数がピークから減り始めたら（群れが帰り始めたら）、
取りこぼす前に即発報します。「完璧な瞬間」を待ちすぎて全部逃すのを防ぐ保険です。

## 通信とフェイルセーフ

罠は山中にあり回線が不安定な前提で設計しています。

- **作動は BLE ローカル制御を主**（`bleak` で SwitchBot Bot を直接 press）。インターネット不要で発報。
- **クラウド API は副**（通知・遠隔監視の best-effort）。
- **作動は必ず結果を確認**し、失敗時は即リトライ＋別チャンネル通報。

---

## 省電力（無人長期運用）

- 常時 AI 推論はバッテリを消耗します。**動体検知（フレーム差分／PIR）で wake** し、
  動きがある時だけ YOLO 推論を回します（`power.motion_gated: true`）。
- 夜間はIRカメラ前提。モデルは軽量（YOLOv8n / NCNN）を推奨。

## セットアップ

```bash
pip install -r requirements.txt

# 囲い罠・箱罠 (SwitchBot でゲートを落とす)
python main.py --list-devices      # SwitchBot デバイスID確認
python main.py                     # 監視開始
python main.py --no-display        # 画面なし (Raspberry Pi)

# くくり罠 (ソレノイド電磁ロック。設計は docs/snare_design.md 必読)
python snare_trap.py               # interlock モード (推奨)
python snare_trap.py --headless    # 画面なし
```

## くくり罠はなぜ別プログラムか

くくり罠は足が踏板に載っている時間が **0.3〜0.6秒** しかなく、カメラ→AI→SwitchBot の
電子トリガー (最良1.3秒) では間に合いません。そこで発想を逆転し、
**遅延ゼロの機械式トリガーを残したまま、AIが「イノシシ確認中」の間だけ電磁ロックを解錠する**
インターロック方式を採っています。これで応答速度の問題が消え、副次的に
カモシカ・イヌ・人の錯誤捕獲を構造的に防げます。詳細: `docs/snare_design.md`

## 重要：モデルについて
標準 YOLOv8（COCO）にイノシシ・シカのクラスはありません。**現地の画像で学習した
カスタムモデル**（`models/wildlife.pt`、クラス例: `boar, deer, human, bear, dog, serow`）が必要です。
`human/bear/dog/serow` を学習に含めることが、錯誤捕獲防止の生命線です。

## 法令・安全の注意
- くくり罠・囲い罠の使用には**狩猟免許と設置許可**が必要です。
- 錯誤捕獲・鳥獣保護法・動物愛護（早期の見回り・止め刺し）を必ず遵守してください。
- 本システムは人の見回りを**支援**するものであり、無人放置を推奨するものではありません。
